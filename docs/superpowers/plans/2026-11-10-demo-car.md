# Demo Car Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new profile can create a made-up German BMW 320d with ~3.5 years of trips, maintenance and expenses, delete it, and have it removed automatically when a real car is added.

**Architecture:** A pure deterministic generator in Core (`DemoData.Generate`) builds domain-like records; a Web service writes them for the current user in one transaction on a vehicle flagged `IsDemo`; new endpoints create/delete it and the existing create-vehicle endpoint removes demos. The React first-car screen gets a demo button and a banner shows on demo cars.

**Tech Stack:** .NET 10, EF Core + SQLite, xUnit (Core + Web tests with `ApiFactory`), React + TanStack Query + vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-demo-car-design.md` — read it first; all data values (car, places, prices, intervals) come from its "The demo car" section.

## Global Constraints
- Branch `feat/hosted-auth`; commit per task; commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` (the implementer's own model line).
- TDD order: write the failing test, run it, see it fail, then implement. Do not skip.
- UI dates dd/mm/yyyy (use `fmtDate` from `web/src/lib/format.ts`); never US style.
- Demo deletion must only ever touch vehicles with `IsDemo == true` of the current user.
- No real data in git; no files on disk for the demo (no documents).
- `dotnet build` must stay at 0 warnings; all existing tests stay green.

## Review Focus
1. Generation relative to `today` near month ends / leap days (e.g. today = 2026-02-28, 2028-02-29) → purchase date clamps, no exceptions, no dates after today. Test in Task 1.
2. Creating a real car while the demo is the selected/default vehicle → the real car becomes default and the UI selects it (stale `localStorage` vehicle id must fall back). Test in Task 2 (API default) and Task 3 (App falls back when stored id is gone — already `find(...) ?? default`, assert in test).
3. Deleting a default demo while another car exists (cannot happen through the API today, but rows from older data or a future "add car" path could) → the remaining car becomes default. Test in Task 2.
4. Analytics endpoints on the demo car (overview, ownership, intervals, maintenance, charts, statistics) must return 200, not 500. Test in Task 2.
5. Double-click on "Try with a demo car" → only one demo (button disabled while pending; API refuses a second). Tests in Task 2 and Task 3.

  ```csharp
  namespace DriverBalance.Core;
  public sealed record DemoTyreSet(string Key, string Name, string Brand, string Model, string Size, TyreSeason Season, DateOnly? PurchaseDate, bool Retired);
  public sealed record DemoExpense(DateOnly Date, ExpenseCategory Category, decimal Amount, int? Odometer, string? Note,
      DateOnly? CoversFrom, DateOnly? CoversTo, double? Litres, bool? FullTank, string? Station, string? Place,
      MaintenanceType Flags, IReadOnlyList<MaintenanceWork>? Work, string? TyreSetKey);
  public sealed record DemoCar(string Name, string FuelType, string HomeCurrency, string TimeZone,
      DateOnly PurchaseDate, DateOnly HistoryStart, int HistoryStartOdometer, decimal EstimatedResaleValue, DateOnly ResaleEstimateDate,
      string Model, string Engine, string Trim, int ModelYear, string ExteriorColour, string Interior, IReadOnlyList<string> Equipment,
      string Transmission, bool Awd, string InitialTyreSetKey,
      IReadOnlyList<DemoTyreSet> TyreSets, IReadOnlyList<Trip> Trips, IReadOnlyList<DemoExpense> Expenses);
  public static class DemoData { public static DemoCar Generate(DateOnly today, int seed = 2026); }
  ```
  `Trip` is the existing `DriverBalance.Core.Trip` record (Category `"Private"`, local Europe/Berlin wall-clock `DateTime`s, Kind Unspecified). Amounts in EUR; Purchase category used for the car (~58 900) and registration (~180). Tyre swaps: category Maintenance, `Flags = TyreSwap` (plus `NewTyres` when new tyres fitted), `TyreSetKey` = the set fitted. Winter set purchase: category Tyres. Fuel type string `"DieselMhev"`.

**Interfaces:**
- Consumes: `DemoData.Generate(DateOnly today, int seed)` and the records from Task 1.
- Produces:
  - `POST /api/vehicles/demo` → 201 `VehicleDto` (`isDemo: true`). 400 `"You already have a car."` if the user has any vehicle.
  - `DELETE /api/vehicles/{vid}` → 204; 400 `"Only the demo car can be deleted."` for a non-demo; 404 for unknown/other user's.
  - `POST /api/vehicles` (existing): after saving the new car, deletes the user's demo vehicles and makes the new car default.
  - `VehicleDto.IsDemo` (JSON `isDemo`).
  - `public sealed class DemoCarService { Task<VehicleRow> CreateAsync(CancellationToken ct); }` — today from `VehicleDataLoader.TodayFor` (Europe/Berlin) or `TimeProvider`; one transaction; vehicle (`IsDemo = true`, `IsDefault = true`, `ParametersJson = new AnalysisParameters().ToJson()`, details via `CarDetails(...).ToJson()`), tyre sets, `InitialTyreSetId` = the set for `InitialTyreSetKey`, an `ImportBatchRow` named `"Demo data"` owning the trips (`Imported` = count, first/last dates), trips, expenses (`Currency = "EUR"`, `Source = Web`, `WorkJson` serialised the same way `ExpenseEndpoints` does, `MaintenanceFlags = (int)Flags`, `TyreSetId` mapped from key).
  - `public static class VehicleDeletion { Task DeleteAsync(DriverBalanceDbContext db, DocumentStore documents, long vehicleId, CancellationToken ct); }` — expenses first (they restrict tyre sets), then the vehicle row (cascade trips/tyre sets/batches/documents rows), then `documents.DeleteVehicleFolder(vehicleId)`; if the deleted car was default, the remaining lowest-id vehicle becomes default.
